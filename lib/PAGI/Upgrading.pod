=head1 NAME

PAGI::Upgrading - What changed between sub-spec versions, and what to do about it

=head1 DESCRIPTION

Each section below covers one version of the HTTP/WebSocket/SSE sub-spec
(L<PAGI::Spec::Www>), newest first, split by audience: application authors
writing to the raw spec, framework authors, and server implementers. The
version a server implements is C<< $scope->{pagi}{spec_version} >>.

=head1 0.5 TO 0.6

Sub-spec 0.6 makes the connection state object universal, adds C<abort> and
C<disconnect_detail>, and makes refusing a WebSocket handshake or an SSE
stream an ordinary HTTP response. These are new requirements, so
C<spec_version> moves to C<'0.6'>.

=head2 Application authors

=head3 pagi.connection is on every scope

C<< $scope->{'pagi.connection'} >> is now present on C<websocket> and C<sse>
scopes, with the same interface as on C<http>. Use it instead of watching
the receive queue for a disconnect while you wait on something else.

Before, the only signal was the queue, and racing it required protecting
the live receive from cancellation:

    my $gone   = $receive->();
    my $lookup = $quota->lookup($scope);
    await Future->wait_any($lookup, $gone->without_cancel);
    if ($gone->is_ready) { ...; return }
    # after a completed refusal, $gone never resolves and may not be cancelled

After:

    my $conn   = $scope->{'pagi.connection'};
    my $lookup = $quota->lookup($scope);
    await Future->wait_any($lookup, $conn->disconnect_future);
    return unless $conn->is_connected;

C<disconnect_future> returns a fresh, cancellation-isolated observer on
every call; losing a race cancels nothing else. Register C<on_complete> and
C<on_disconnect> for audit and cleanup; they fire on every ending including
a completed refusal. C<on_disconnect> callbacks now receive
C<($reason, $detail)>; C<disconnect_detail> is diagnostic text, never a
branching key.

=head3 abort

C<< $conn->abort($detail) >> ends the scope's transport deliberately. The
scope ends abnormally with token C<app_abort>, later sends are no-ops, and
the server logs no error. Use it where you previously had no honest option:
a middleware cutting off a stream that exceeded a quota, a handler giving
up on a client.

=head3 Refusing a WebSocket handshake or an SSE stream

Send an ordinary HTTP response on the scope before C<websocket.accept> or
C<sse.start>. The C<websocket.http.response.*> and C<sse.http.response.*>
events are gone, and so is the C<extensions> check.

Before:

    if ($scope->{extensions}{'websocket.http.response'}) {
        await $send->({ type => 'websocket.http.response.start', status => 401, headers => [...] });
        await $send->({ type => 'websocket.http.response.body', body => 'unauthorized' });
    } else {
        await $send->({ type => 'websocket.close', code => 1008 });   # bare 403
    }

After:

    await $send->({ type => 'http.response.start', status => 401, headers => [...] });
    await $send->({ type => 'http.response.body', body => 'unauthorized' });

C<websocket.close> before accept now fails as an out-of-sequence send.
Refusal bodies stream when C<< more => 1 >>, exactly like HTTP bodies:
finish them or watch the connection object, because a refusal you abandon
after its start is an incomplete response. Prefer a complete body.

=head3 sse.disconnect before sse.start

C<sse.disconnect> can arrive before C<sse.start>; the previous wording
suggested otherwise. Servers already behaved this way.

=head2 Framework authors

=over 4

=item *

Handler objects for WebSocket and SSE may consult the connection object
instead of duplicating its state. A streaming response helper races the
object, never the queue.

=item *

On caller cancellation of a streaming response, call C<abort> so the wire
reflects it.

=item *

Drop denial capability detection, bare-403 fallbacks, and any bridge that
renamed HTTP response events to protocol-prefixed ones. Middleware that can
refuse a request needs exactly one arm.

=item *

Log C<disconnect_detail> alongside the token.

=item *

Gate on C<spec_version>: a scope reporting 0.6 or later carries the object
unconditionally. Below that, refuse a streaming response through a refusal
path rather than proceeding into a hang.

=back

=head2 Server implementers

=over 4

=item *

Attach a connection state object to every C<http>, C<websocket>, and
C<sse> scope; implement every accessor plus C<abort>; add the C<app_abort>
token; populate C<disconnect_detail> where you know more than the token.

=item *

Drive the object from the same sites that queue disconnect events and
finish clean responses; the object's reason and the event's reason must be
the same token. See L<PAGI::Spec::Www/"Meaning per scope">.

=item *

Accept the HTTP response events on C<websocket> scopes before accept and
on C<sse> scopes before start, through your ordinary HTTP response path.
Remove the protocol-prefixed refusal events and the
C<websocket.http.response> extension advertisement. Fail C<websocket.close>
before accept.

=item *

Report C<< spec_version => '0.6' >> once all of the above is in place.

=back

=head2 Known issue

A request whose C<Accept> header carries C<text/event-stream> alongside
other media ranges (htmx 4 with its SSE extension loaded sends
C<text/html, text/event-stream> on every request) is classified as an
C<sse> scope by L<PAGI::Spec::Www/"SSE Connection Detection">. An
application that handles only C<http> scopes therefore returns an error to
those requests. The specification's stated correction path is to answer
the C<sse> scope with an ordinary HTTP response (see
L<PAGI::Spec::Www/"Refusing the stream">), which now costs no special
events. Every application and every scope-gated middleware must do so. A
structural fix is planned for a later version.
